# Compact system navigation — 17.11.2026

Approved preview: compact-system-menu.html, refined to remove fleet/driver and holdings and place configuration in Settings.

- New-order action and seven daily destinations remain at root: dashboard, orders, production queue, inventory, procurement, customers, reports. Projects nest under the direct Customers link. If the parent is unavailable for a role but Projects is allowed, Projects remains reachable in More.
- More contains intake, warehouse, quality/maintenance and finance. Finance links directly to its screen and optionally expands pricing/profitability; it remains a disclosure-only parent if only child permissions exist. Settings contains machine/terminal/production setup, general scanner, worker collection, support/bugs and administration. Existing personal worker portal navigation is separate and unchanged.
- Fleet/driver, holdings and War Room shortcuts are omitted from every shell navigation render. Fleet/holdings duplicate admin quick cards are removed. Screen metadata, route guards, operational loading/certificate processes, historic data and module administration remain intact; no dependency-blind code/data deletion or module deactivation.
- Desktop and mobile drawer share buildNavigation and the same filtered links. The phone bottom bar exposes dashboard, orders, queue, inventory and a menu action. Scanner moves under Settings; its existing universal authenticated access and server authorization of decoded destinations remain unchanged. This intentionally supersedes the previous bottom-bar scanner shortcut.
- Licensed module IDs and visible screen IDs are separate states; permittedLink intersects them. A later license response cannot restore role-hidden entries and a later role refresh cannot restore unlicensed entries. Existing currentScreenId checks still guard bookmarked removed screens. Pricing/profitability inherit the Finance screen permission where no separate manifest screen exists; their server API permissions remain authoritative.
- Secondary groups default closed on daily screens, open for the current child page and retain explicit user expansion/close state across refresh. Native buttons expose aria-expanded/controls; child IDs are unique between drawer/sidebar, selected anchors have aria-current. Outside click/Escape collapses groups, and clicks inside a re-rendered toggle stop propagation so the same click cannot immediately close the new group. Mobile link closing uses delegation, surviving role/license re-renders.
- Scope: public/nav.js and obsolete admin quick links. No server route, database, access grant, production or stock change. No desktop/browser automation per prior user instruction.

Validation: 155 focused shell/auth/governance checks, five behavior tests for hierarchy/permissions/rendering and final rebased full suite 1,391 passed. QR/UI contract now checks the approved Settings entry rather than the former bottom-bar scanner slot; scan authorization, protocol handling and loading certificate checks remain. No browser/phone visual verification was performed.
