# מערכת קריאות שירות וסוכן תקלות

המסך `/bugs.html` מרכז פתיחת תקלה, תמונות עם סימונים, טיפול ואישור סגירה. נדרשים רק תיאור התקלה והישג נדרש. חיבור לסוכן הוא רכיב נפרד: קריאות נשמרות בתור גם כאשר אין סוכן מחובר, והמסך מציג זאת במפורש.

## דיווח וטיפול

1. ממלאים תיאור תקלה והישג נדרש. אפשר להוסיף עד שלוש תמונות JPG, PNG או WebP, עד ארבעה מ״ב לתמונה.
2. ליד תמונה בוחרים ״צייר / סמן״. אפשר לצייר בעיפרון, להוסיף חץ או מסגרת, לבחור צבע ולבטל סימון. שמירת הסימונים יוצרת תמונה מצורפת עם הסימונים.
3. ב״טיפול ומעקב״ רואים את הקריאה, התמונות והיסטוריית הטיפול. מטפל מורשה יכול לדווח איך טופל ולצרף תמונת תוצאה או אסמכתת בדיקה.
4. ״טופל — שלח לבדיקה״ אינו סוגר את הקריאה. המדווח בודק, מאשר סגירה או מחזיר לטיפול. אפשר לפתוח מחדש תקלה שחזרה.

רק מנהל רואה את כל הדיווחים. משתמש רגיל רואה את הדיווחים שלו ואת התמונות שלהם. קישור לצ׳אט מעתיק את פרטי הקריאה בלבד ואינו מפעיל סוכן מאחורי הקלעים.

## חיבור סוכן

מנהל יוצר חיבור דרך ״ניהול חיבור הסוכן והדיווחים הישנים״. המפתח מוצג פעם אחת, תקף לשבעה ימים וניתן לביטול. הוא מעניק גישה לתור התקלות ולתמונות של הקריאה שהוקצתה לסוכן בלבד; הוא אינו JWT של משתמש ואינו מעניק גישה להזמנות, לנתוני ייצור, לכספים או להגדרות.

יש להפעיל את הסוכן במחשב פיתוח או בסביבה מבודדת, לא בתוך שרת הייצור. נדרשים Node.js, Git ו־Codex CLI מותקן ומחובר. אין לשלוח את המפתח בצ׳אט או לשמור אותו במאגר הקוד.

משתני הסביבה של תהליך הסוכן:

| משתנה | ערך |
| --- | --- |
| `FAULT_AGENT_URL` | כתובת המערכת, למשל `https://ironbend-hmd.onrender.com` |
| `FAULT_AGENT_TOKEN` | המפתח המוגבל שהונפק במסך התקלות |
| `FAULT_AGENT_REPO` | נתיב מוחלט לעותק קוד נקי ומעודכן עם תלויות מותקנות |
| `FAULT_AGENT_CODEX_JS` | נתיב מוחלט ל־`@openai/codex/bin/codex.js` המותקן |
| `FAULT_AGENT_PUBLISH_SCRIPT` | אופציונלי: נתיב מוחלט לעותק המהימן של `scripts/fault-agent-publish.js` מחוץ לסביבת עבודת הסוכן |
| `FAULT_AGENT_PUBLISH_CONFIG` | אופציונלי: נתיב מוחלט לקובץ הגדרות פרסום פרטי, מחוץ לסביבת עבודת הסוכן |

להפעלה מתמשכת:

```powershell
node scripts/fault-agent-worker.js
```

לבדיקת קריאה יחידה משתמשים ב־`--once`. הסוכן אוסף קריאה, מוריד את תמונותיה לתיקייה מבודדת, יוצר עותק של קוד המקור ללא מסד נתונים וסודות, ומפעיל Codex עם `workspace-write`, ללא רשת לכלי ההרצה וללא טעינת תצורת המשתמש. מפתח חיבור התקלות אינו מועבר לתהליך התיקון. סביבת העבודה נשמרת כראיה; אין מחיקה רקורסיבית אוטומטית.

אופן ההפעלה הלא־אינטראקטיבי מבוסס על [תיעוד OpenAI הרשמי](https://learn.chatgpt.com/docs/non-interactive-mode). יש לאמת בידוד ותלויות בסביבת ההתקנה לפני הפעלת פרסום אוטומטי.

## פרסום אוטומטי

ללא רכיב פרסום מוגדר הסוכן מכין תיקון בלבד, והמסך מציג ״תיקון קוד מוכן — טרם הועלה״. אין לסמן תוצאה זו כתיקון שבוצע בתוכנה החיה.

רכיב הפרסום המצורף מיועד למערכת שבה דחיפה לענף הייצור מפעילה פריסה אוטומטית. קובץ הגדרות הפרסום הפרטי מכיל:

```json
{
  "repo": "C:/absolute/path/to/clean-checkout",
  "remote": "origin",
  "branch": "main",
  "public_origin": "https://ironbend-hmd.onrender.com"
}
```

יש להתקין את הסקריפטים המהימנים ואת הקובץ הפרטי מחוץ לתיקיית העבודה הזמנית של הסוכן, ולהגן עליהם באמצעות הרשאות מערכת ההפעלה. הפרסום משתמש בהרשאות Git של מפעיל הסוכן; אין צורך לתת לתהליך התיקון מפתח ניהול של Render.

לפרסום אוטומטי מותרים עד חמישה עשר קובצי ממשק ברמה העליונה של `public`. מסכי אימות, הרשאות, ניהול, פורטלים, ניווט ו־service worker מוחרגים. שינוי קוד שרת, מסד נתונים, קבצים אחרים או מחיקת קובץ נעצר לבדיקה. תיקון תוכנה אינו הרשאה לשנות רשומות הזמנה; שינוי נתונים דורש אישור נפרד וביצוע באמצעות משתמש מורשה.

לפני פרסום נבדק שענף היעד עדיין זהה לגרסת הבסיס. הקבצים המאומתים מועתקים לעותק Git נפרד, מופעלת כל חבילת הבדיקות המהימנה, ונוצר commit ללא `force push`. רק לאחר שאומת כי הקבצים החיים תואמים לקבצים שנבדקו מוחזרת התוצאה ״תוקן״. אם הפרסום או האימות נכשלים, יש לבדוק את מצב הפריסה לפני ניסיון נוסף; תור הסוכן אינו מנסה שוב אוטומטית.

## הרשאה ותיעוד

לכל קריאה מוקצה lease מוגבל בזמן. סוכן אחר אינו יכול לדווח על אותה עבודה או להוריד את תמונותיה. ביטול חיבור, אובדן lease או העברת הטיפול ידנית מונעים עדכון מאוחר של הסוכן. פעולת סוכן אינה סוגרת דיווח: סגירה דורשת אישור מדווח או מנהל, עם תיעוד תיקון.

יצירת מפתח חיבור מעניקה גישה מוגבלת לנתוני תקלות ותמונות. יש לקבל אישור מנהל בזמן החיבור. אין להפעיל את הסוכן או את רכיב הפרסום רק מפני שהמסך החדש נפרס.

## החלפת הדיווחים הישנים

איפוס הדיווחים זמין למנהל מערכת בלבד. המערכת מציגה את מספר הדיווחים והתמונות לפני האיפוס ודורשת את הנוסח ״מחיקת התקלות הישנות״. אם נפתח דיווח נוסף בינתיים, האיפוס נעצר ודורש בדיקה מחדש. טיפול סוכן פעיל חוסם איפוס.

האיפוס שומר תחילה גיבוי פרטי ב־`fault_report_backups`, ובאותה עסקה מוחק את התור, התמונות, האירועים והדיווחים מטבלאות התקלות הפעילות. אין שינוי בטבלאות הזמנות או בתעודות משלוח. הגיבוי ניתן להורדה למנהל מערכת בלבד וכולל תמונות ב־Base64.

ב״גיבויים ושחזור דיווחים״ מנהל מערכת יכול לשחזר גיבוי פעם אחת. השחזור מוסיף קריאות במספרים חדשים, כולל ההיסטוריה והתמונות, בלי לדרוס קריאות קיימות ובלי להפעיל מחדש עבודות סוכן ישנות. אם אין די מקום לתמונות, השחזור נעצר ללא שינוי חלקי.

## בדיקות

```powershell
node --test test/bug-reports.test.js test/fault-desk.test.js
node --test test/*.test.js
```

בדיקות השירות מכסות הרשאות, יצירה חוזרת ללא כפילות, שמירת תמונות, הקצאת סוכן, ביטול חיבור, מניעת דריסת טיפול ידני, הפרדת תיקון מוכן מתיקון חי וגיבוי לפני איפוס. בדיקת דפדפן מקומית מכסה צירוף תמונה, ציור מסגרת, פתיחת קריאה, תיעוד טיפול ואישור סגירה. יש לבצע בדיקת התקנה נפרדת עם סוכן אמיתי ועם צינור הפריסה לפני הפעלת תיקונים אוטומטיים בייצור.
